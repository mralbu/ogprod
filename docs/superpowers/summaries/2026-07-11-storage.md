## What was built

ogprod went from "connectors that parse publisher files into canonical
frames" to a queryable local store with geometry:

- **Entities schema** (`schema.ENTITY_COLUMNS`, `validate_entities`) — a
  second canonical table joining production on `(source, entity_id)`:
  wells as Points, field ring fences as (Multi)Polygons, EPSG:4326,
  missing geometry allowed, duplicate ids and null periods/sources
  rejected.
- **Connector interface** — `parse_entities`/`fetch_entities` on the
  `Source` ABC plus `base.build_entities`, mirroring the existing pure
  parse / optional fetch split.
- **Store** (`ogprod.store`) — Parquet/GeoParquet as the storage format,
  DuckDB as the query engine only. Production is hive-partitioned
  (`production/source=*/year=*/data.parquet`) with upsert on
  `(source, entity_id, period, product)` by atomic partition rewrite;
  entities are one GeoParquet per source, whole-file replaced. Readers:
  `load_production` (filter pushdown), `load_entities`, `sql` (views
  `production` + `entities`). Root: `data/store/`, `$OGPROD_STORE`, or
  per call.
- **CLI** — `python -m ogprod ingest <source> [--entities]` chains
  fetch → parse → upsert, writing file-by-file; `just ingest`.
- **Geometry connectors, live-verified July 2026:**

  | Source | Live endpoint (documented one had drifted) | Result |
  |---|---|---|
  | sodir | FactMaps ArcGIS DataService GeoJSON, layer 7100 (shapefile zip 404s) | 141 fields; 129/132 producing fields join |
  | anp | GeoServer WFS `BD_ANP:POCOS_SIRGAS` CSV (gov.br cadastre page 404s) | 31,273 wells, 0 missing coords; 6,654/6,655 join (2023-06) |
  | argentina | wells-listing CSV resource inside the `produccion-de-petroleo-y-gas-por-pozo` CKAN dataset (standalone dataset id 404s) | 84,242 wells, 0 missing coords; 99.93% join (2024) |

## Decisions worth remembering

- **Files are the database.** Rejected a single DuckDB file: opaque,
  single-writer, and the static-site goal needs plain files anyway. The
  same Parquet works under DuckDB-WASM later.
- **Upsert = partition rewrite,** because publishers restate whole
  months/years; never append. Duplicate keys within one write keep the
  last occurrence, which is what lets ANP's pré-sal file (a subset of the
  mar file, byte-identical values) upsert harmlessly.
- **Geometry is a first-class connector output,** not a side-loaded
  dataset — fetched, parsed, and validated exactly like production.
- **entity_id conventions per source:** sodir = field NPDID (normalized
  through Int64 to survive float promotion), anp = well name (unique in
  the live cadastre; verified), argentina = `idpozo`.
- **Website contract (future):** rollup JSON for dashboards, PMTiles for
  the map, per-field series JSON for click-to-chart — spec §4; exporter
  not built.

## Publisher drift encountered (and where the fix lives)

All three publishers had moved off their documented endpoints between the
plan and implementation. Each connector documents the live endpoint in its
module docstring; column-name drift is absorbed by alias tables at the top
of each connector (`_ENTITY_ALIASES`, `_ENTITY_META_ALIASES`), which are
the designated extension points. Live data also forced geometry repair in
sodir (null-geometry features, self-intersecting rings → `make_valid`
before dissolve), covered by offline fixtures.
